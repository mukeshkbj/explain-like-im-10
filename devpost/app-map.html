ELI10 App Map

A short guide to how ELI10 works and where to make changes. This is a snapshot of the code at the commit noted at the bottom, so it may drift later.

What it is

ELI10 turns a confusing document into four plain-language sections: In short, What you need to do, Watch out for and Questions to ask. Every point keeps the exact quote it came from, so you can click it and check it against the original. There are three main pieces:

PieceFileJob
The pagepublic/index.html, public/app.js, public/style.cssTakes the text, shows the card, and highlights sources
The quote matcherpublic/match.jsFinds each AI quote inside the original text
The serverserver.js, lib/explain.jsKeeps the API key secret and asks Gemini for structured JSON

One action: press "Explain it"

Reference route (three stops)

Open the project in your editor and follow one click through the code. Search for each anchor in its file.

  1. public/app.js — search async function explain
    Runs when you press Explain it. It turns on the loading state, POSTs your text to /api/explain, then calls render(). If the request fails, it shows a friendly error and leaves your text in the box.
  2. lib/explain.js — search INSTRUCTIONS and RESPONSE_SCHEMA
    These are the rules Gemini follows: use short words, copy every source_quote word for word, and don't invent anything. The schema forces the answer into the four sections. explain() gives each call 30 seconds and falls back to lighter Gemini models (FALLBACK_MODELS) when the main one is busy or over quota.
  3. public/match.js — search export function findQuote
    This is the trust feature. It looks for each quote in the original, first exactly, then ignoring spacing, case and curly quotes. renderOriginal() in app.js wraps each match in a <mark>, and activate() highlights it and scrolls to it when you click a point. A quote with no match shows "source not found in the original".

A practice to reuse

Make the AI show its evidence, then check it with code. The scope (devpost/scope.md → The Unique Kernel) said every point must carry a quote from the original, and the spec flagged the risk that Gemini might not copy quotes word for word. Instead of trusting the model, the build added a measurable check: npm run check runs the three samples and counts how many quotes findQuote() actually finds (30 of 30 at this snapshot). The app also has an honest fallback, "source not found", for when the check fails.

The same idea works on other AI projects: ask the model for structured output that includes something checkable, then write a small script that measures it.

Run it again

cp .env.example .env    # add GEMINI_API_KEY
npm start               # http://localhost:3000
npm run check           # matcher cases + live quote check (server running)
Where the key lives

The Gemini key is only read by server.js from .env, which git ignores. The browser never sees it.
